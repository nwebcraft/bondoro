# Capability: スクレイピング

商品情報の収集と重複排除を担当する。

## ADDED Requirements

### Requirement: ECサイトからの商品情報取得

システムは、複数のECサイトから「ボンボンドロップ」関連商品の情報を定期的に取得しなければならない（SHALL）。

対象サイト:
- 楽天市場（楽天商品検索API使用）
- Yahoo!ショッピング（Yahoo!ショッピングAPI使用）

> **Note:** Amazon PA-APIはアソシエイト審査が必要なため、MVP後に追加予定。

取得情報:
- 商品タイトル
- 価格
- 商品URL
- 商品画像URL（任意）

#### Scenario: 楽天市場から商品情報を取得

- **WHEN** スクレイピングLambdaが実行される
- **AND** 楽天商品検索APIが正常に応答する
- **THEN** 「ボンボンドロップ」をキーワードとした検索結果が取得される
- **AND** 各商品の情報がDynamoDBに保存される

#### Scenario: APIがエラーを返す場合

- **WHEN** スクレイピングLambdaが実行される
- **AND** ECサイトのAPIがエラーを返す
- **THEN** エラーがログに記録される
- **AND** 他のサイトの処理は継続される

### Requirement: アメブロからの入荷情報取得

システムは、アメブロから「ボンボンドロップ」に関する入荷情報を含むブログ記事を取得しなければならない（SHALL）。

#### Scenario: アメブロRSSフィードから記事を取得

- **WHEN** スクレイピングLambdaが実行される
- **AND** アメブロのRSSフィードにアクセスする
- **THEN** 「ボンボンドロップ」「BONBON DROP」を含む記事が抽出される
- **AND** 記事情報がDynamoDBに保存される

#### Scenario: RSS取得失敗時のフォールバック

- **WHEN** RSSフィードの取得に失敗する
- **THEN** HTMLスクレイピングにフォールバックする
- **AND** 処理結果がログに記録される

### Requirement: 定期実行

システムは、EventBridgeスケジュールにより数時間ごとに自動実行されなければならない（SHALL）。

#### Scenario: スケジュール実行

- **WHEN** EventBridgeがスケジュールイベントを発火する
- **THEN** スクレイピングLambdaが起動される
- **AND** 全対象サイトからの情報取得が実行される

### Requirement: 重複排除

システムは、同一商品の重複登録を防止しなければならない（SHALL）。

重複判定基準:
- 商品URLのハッシュ値が一致する場合は同一商品とみなす
- ソースが異なる場合は別レコードとして保存する

#### Scenario: 新規商品の登録

- **WHEN** 新しい商品URLが検出される
- **THEN** 商品情報がDynamoDBに保存される
- **AND** `notified: false` として記録される

#### Scenario: 既存商品の再検出

- **WHEN** 既にDynamoDBに存在する商品URLが検出される
- **THEN** `last_seen_at` のみが更新される
- **AND** `notified` の値は変更されない
- **AND** 重複した商品は新規としてカウントされない

### Requirement: レートリミット遵守

システムは、各サイトのAPI利用規約およびアクセス制限を遵守しなければならない（SHALL）。

#### Scenario: APIレートリミット

- **WHEN** APIリクエストを送信する
- **THEN** 各APIの制限を超えないよう間隔を空ける
- **AND** 429エラーを受けた場合は適切にリトライする
